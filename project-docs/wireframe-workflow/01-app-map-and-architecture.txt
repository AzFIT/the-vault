KEY ARCHITECTURE RULES (worth copying)
──────────────────────────────────────
1. Pages are THIN. All logic lives in components/ and lib/.
2. One data file (mock.ts). Every page derives from it — never
   invent parallel data inside a page.
3. Pure engines separated from UI: planBlueprint.ts does math only;
   the page renders its output. Unit-testable.
4. localStorage acts as the "database" behind tiny modules
   (enquiries.ts, sheets/store.ts) — each has ONE function
   (submitEnquiry / store mutation) that you later swap for a
   Supabase insert. Nothing else in the app changes.
5. Every overlay (modal/drawer/palette): role="dialog", ESC to close,
   backdrop click to close, body scroll lock.
